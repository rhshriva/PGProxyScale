# PostgreSQL Proxy: Technical Innovation Frontier

## 1. Wire protocol mechanics a proxy can exploit

v3 startup negotiates the protocol version (`3.0` = 196608; PG18 adds `3.2`), then auth, `ParameterStatus`, `BackendKeyData`, `ReadyForQuery` ([protocol-flow](https://www.postgresql.org/docs/current/protocol-flow.html)). The extended protocol is `Parse`/`Bind`/`Describe`/`Execute`/`Sync`/`Flush`/`Close` ([message formats](https://www.postgresql.org/docs/current/protocol-message-formats.html)). Key asymmetries: **unnamed** statements die on the next `Parse` *and on any simple `Query`*, while named ones persist until `Close`; after an error the backend skips to the next `Sync`; completion must be counted by `ReadyForQuery`, not `CommandComplete`. Pipelining therefore works only inside a Sync-delimited batch ([pipeline mode](https://www.postgresql.org/docs/18/libpq-pipeline-mode.html)). `CancelRequest` arrives on a **separate** connection with (PID, secret) and is silently dropped on mismatch — under `SO_REUSEPORT` it lands on the wrong process, which is why PgBouncer grew a `[peers]` forwarding protocol ([config](https://www.pgbouncer.org/config.html)); PG18's variable-length cancel keys (to 256 bits) break fixed 12-byte assumptions ([PG18 notes](https://www.postgresql.org/docs/18/release-18.html)). PgBouncer's `max_prepared_statements` maps each unique query to `PGBOUNCER_{id}`, rewrites client names, and re-`Parse`s on a fresh server connection with an LRU per connection (default 200); SQL-level `PREPARE` is untracked and DDL can raise "cached plan must not change result type" ([config](https://www.pgbouncer.org/config.html)). pg_doorman remaps anonymous `Parse` to `DOORMAN_<N>` so plans are reused pool-wide, synthesising `ParseComplete` on hits ([docs](https://ozontech.github.io/pg_doorman/tutorials/prepared-statements.html)). COPY uses `CopyData` framing (pass through, don't buffer); `Bind` carries per-column binary format codes; `SSLRequest`/`GSSENCRequest` precede startup and PG17 `sslnegotiation=direct` saves a round trip ([libpq](https://www.postgresql.org/docs/current/libpq-connect.html)). PG18 adds `OAUTHBEARER` OAuth2; PG19 is preparing "protocol grease" ([commit](https://www.postgresql.org/message-id/E1voQy7-001Wl6-2v@gemulon.postgresql.org)).

## 2. SQL parsing at the proxy

`libpg_query` vendors the real server parser (parse/scan/fingerprint/PL-pgSQL) and underpins pg_query_go, pg_query.rs, pglast ([libpg_query](https://github.com/pganalyze/libpg_query)). Fingerprinting hashes the parse tree so literals and formatting vanish. Cost is a C dependency with per-major-version branches, and pure-Rust parsers are not equivalent — datafusion-sqlparser-rs lacks Postgres operators, which is why PgCat has an open issue to switch and PgDog embeds the native parser ([pgcat #620](https://github.com/postgresml/pgcat/issues/620), [pg_raw_parse](https://github.com/pgdogdev/pg_raw_parse)). Full parsing costs real latency: PgDog profiled protobuf AST conversion dominating, replaced it with direct C→Rust FFI, and measured parse 613→3,357 q/s and deparse 759→7,319 q/s (+25% pgbench) ([PgDog](https://pgdog.dev/blog/replace-protobuf-with-rust)). Fast path: parse once per unique statement text (hash → cached AST), never per `Bind`/`Execute`; skip SQL entirely when routing needs only the `ReadyForQuery` status byte (PgBouncer's model). `pg_stat_statements` derives `queryid` by *jumbling* the parse tree; PG18 changed jumbling for constant lists and same-relation names ([notes](https://www.postgresql.org/docs/18/release-18.html), [docs](https://www.postgresql.org/docs/current/pgstatstatements.html)). For plans, `auto_explain` hooks `ExecutorStart` with `log_min_duration` and `sample_rate` ([auto_explain](https://www.postgresql.org/docs/current/auto-explain.html)).

## 3. Caching

Correctness, not storage, is the hard part: a hit must be valid at the *reader's* MVCC snapshot and depends on role/RLS, `search_path` and GUCs, while `volatile` functions (`now()`, `random()`, `nextval()`) are never cacheable. Logical decoding supplies row-level invalidation, but **DDL is not carried by logical replication or decoding** ([restrictions](https://www.postgresql.org/docs/current/logical-replication-restrictions.html)), so schema changes need event triggers or catalog polling. Three shipped camps: TTL/volatility-aware (Cloudflare Hyperdrive parses the wire protocol, refuses `STABLE`/`VOLATILE`, defaults to `max_age` 60 s and never invalidates on write) ([Hyperdrive](https://developers.cloudflare.com/hyperdrive/concepts/query-caching/)); CDC-invalidated (pgcache applies or invalidates per commit, needs primary keys) ([pgcache](https://github.com/PgCache/pgcache)); and IVM (Readyset's wire adapter and **shallow caching** for single-table lookups; pg_trickle inside PG18) ([Readyset](https://readyset.io/docs/concepts/shallow-caching), [pg_trickle](https://pgxn.org/dist/pg_trickle/)). PolyScale sold managed global caching; its exit shows operations and correctness, not cache speed, are the moat.

## 4. New transports

Neon's serverless driver redirects the Postgres wire protocol over WebSockets and HTTP (HTTP for one-shot queries, WS for sessions/transactions, 64 MB cap) ([Neon](https://neon.com/docs/serverless/serverless-driver)). Their round-trip accounting is the artifact: a naive path costs **9 round trips to first result**, cut to 4 via TLS 1.3, pipelining `SSLRequest` with the TLS Client Hello, replacing SCRAM (≈100 ms CPU, unaffordable in a Worker) with TLS-protected password auth, and `TCP_NODELAY` ([Neon](https://neon.com/blog/quicker-serverless-postgres)). gRPC/HTTP-2 proxies must map stream cancellation onto `CancelRequest` and parse binary frames ([Hoop](https://hoop.dev/blog/grpc-prefix-parsing-with-postgres-binary-protocol-proxying-at-production-scale/)). PGlite embeds Postgres as WASM (single-connection; Emscripten cannot fork) ([PGlite](https://github.com/electric-sql/pglite)); ElectricSQL syncs via logical replication ([limitations](https://github.com/electric-sql/electric/issues/1706)). Constraints: stateless transports cannot hold GUCs/temp tables, COPY streaming is awkward, and every request re-pays auth.

## 5. Auth and security innovation

PG18 shipped native OAuth: RFC 6750 bearer tokens, OIDC discovery via `issuer`, pluggable validators, `scope`, IdP→role `map`, and a `delegate_ident_mapping` mode ([PG18 OAuth](https://www.postgresql.org/docs/18/auth-oauth.html)). Prior art: RDS IAM mints ~15-minute tokens ([Bytebase](https://www.bytebase.com/blog/just-in-time-database-access-with-aws-rds-iam/)); Vault issues short-lived dynamic roles with lease revocation and username templating ([Vault](https://developer.hashicorp.com/vault/docs/secrets/databases/postgresql)); PgBouncer supports `auth_type=cert` with CN-derived usernames ([config](https://www.pgbouncer.org/config.html)). Proxy policy is fragmented: pg_ddm does masking plus pooling, proxy-monster does lineage-aware column masking under Cedar with a tamper-evident audit trail ([pg_ddm](https://github.com/emin100/pg_ddm), [proxy-monster](https://github.com/ridi-oss/proxy-monster)); HeliosProxy's WASM plugin ABI adds a residency router that returns a clean `ErrorResponse` when no in-region replica exists ([Helios](https://www.heliosdb.com/docs/proxy/demos/18-residency-router/)). **CVE-2026-85620** (Postgres MCP Pro) bypassed a restricted-mode allowlist because a parser flaw mis-classified a crafted statement ([Forkast](https://forkast.news/postgres-mcp-pro-restricted-mode-bypass-exposes-the-gap-in-ai-database-security/)). Design lesson: enforce on a real AST *and* protocol semantics, keep default-deny privileges in the database, and treat text-to-SQL guardrails as one layer — models still emit injectable SQL ([ToxicSQL](https://arxiv.org/abs/2503.05445)).

## 6. Observability and control plane

eBPF's honest limit: at socket level you see wire bytes and ciphertext under TLS; query text needs uprobes inside the server (`exec_simple_query()`), root, and truncates payloads ([eCapture](https://github.com/gojue/ecapture), [postgres-ebpf](https://github.com/dorkamotorka/postgres-ebpf)). A protocol-aware proxy sees plaintext SQL with no privileges — a durable differentiator. `pg_tracing` emits server spans ([pg_tracing](https://pgxn.org/dist/pg_tracing/0.1.2/doc/pg_tracing.html)); SQLCommenter/OTel appends `/*key='value'*/`, but injected comments *change the SQL string* and cause plan/prepared-cache misses ([SQLCommenter](https://github.com/google/sqlcommenter), [pgbouncer #1044](https://github.com/pgbouncer/pgbouncer/discussions/1044)). Chargeback builds on `queryid` + `total_exec_time`/`temp_blks`/`wal_bytes` ([pg_stat_statements](https://www.postgresql.org/docs/current/pgstatstatements.html)). For overload: Netflix `concurrency-limits` uses Little's Law, Vegas and Gradient2 with per-partition enforcement ([Netflix](https://github.com/Netflix/concurrency-limits)); Google SRE forbids RPS-as-capacity and requires per-customer quotas, criticality classes and retry budgets ([SRE](https://sre.google/sre-book/handling-overload/)); tail latency motivates hedged requests ([Tail at Scale](https://dl.acm.org/doi/10.1145/3046682)).

## 7. Rust/async performance engineering

Tokio's work-stealing pays cross-core wakeups and shared-allocator contention; thread-per-core runtimes (monoio, glommio) plus `SO_REUSEPORT` shard sockets so each core owns state ([monoio](https://github.com/bytedance/monoio), [glommio](https://github.com/DataDog/glommio)). io_uring cuts syscall overhead (it is also PG18's AIO path); zero-copy/`splice` helps COPY passthrough; NUMA pinning and batching matter more than parser micro-tuning. PgDog's published test is the most honest number set: PgDog on 2 Tokio threads vs single-threaded PgBouncer, `pgbench -S`, pool 10 — 15.5k vs 16.7k TPS at 1 connection (libevent wins low), 112k vs 89k at 50, 92.8k vs 76.2k at 2,000, all bottlenecked by Postgres at ~75% CPU ([PgDog](https://pgdog.dev/blog/pgbouncer-vs-pgdog)). PgBouncer gains multi-core only via `SO_REUSEPORT` + peering. Multigres splits client-facing multigateway from a colocated pooler over gRPC and deduplicates prepared statements across gateways ([Multigres](https://multigres.com/blog/two-jobs-two-processes)); SPQR is Yandex's sharding router ([SPQR](https://yandex.cloud/en/docs/managed-spqr/)). The frontier is zero-copy message parsing and per-core sharding of parse/prepared caches.

## 8. Emerging projects worth watching

- **pg_doorman** — MIT Rust pooler, ~3 years in production at Ozon, claims up to 12× TPS vs PgBouncer ([repo](https://github.com/ozontech/pg_doorman)).
- **PgDog** — Rust L7 pooler/load balancer/sharder, native parser, 2PC, online resharding ([repo](https://github.com/pgdogdev/pgdog)).
- **Multigres** — "Vitess for Postgres": gateways, per-user pools, automatic pooling mode ([blog](https://multigres.com/blog/two-jobs-two-processes)).
- **pgwire** — Rust crate ("hyper for the PG wire protocol") supporting 3.0 and 3.2, aimed at building proxies ([repo](https://github.com/sunng87/pgwire)).
- **duckgres** — DuckDB exposing a Postgres server interface ([PostHog](https://github.com/posthog/duckgres)).
- **PGlite** — WASM Postgres with reactive bindings ([repo](https://github.com/electric-sql/pglite)).
- **ElectricSQL** — logical-replication sync with CDN-friendly Shapes ([repo](https://github.com/electric-sql/electric)).
- **pgroll** — reversible zero-downtime migrations via versioned views ([Xata](https://xata.io/blog/postgres-cafe-pgroll)).
- **pgcache / pg_trickle** — CDC-invalidated caching and in-database IVM ([pgcache](https://github.com/PgCache/pgcache), [pg_trickle](https://pgxn.org/dist/pg_trickle/)).
- **OrioleDB** — undo-log MVCC table access method, no VACUUM; still beta ([repo](https://github.com/orioledb/orioledb)).
- **Xata / Tembo / DBLab** — copy-on-write branching, managed extension stacks, ~10 s for a 1 TiB clone ([DBLab](https://github.com/postgres-ai/database-lab-engine)).
- **Retired**: pg_flo (repo 404s) and Tembo's managed service.

## 10 ideas technically feasible today but nobody has shipped well

1. **Protocol-native trace context**: carry trace IDs in a proxy-side index keyed by (connection, Bind), not SQL comments, so `queryid` and plan caches stay intact.
2. **Snapshot-correct result caching**: pgcache proves CDC invalidation; nobody ships a hit that is valid at the reader's MVCC snapshot.
3. **Anonymous-Parse plan caching as a product**: pg_doorman proved `DOORMAN_<N>` remapping; add correct DDL invalidation and per-tenant partitioning.
4. **Cancel routing as a first-class primitive**: PG18's variable-length keys plus multi-process forwarding, exposed as an API.
5. **Agent-scoped credentials via OAuth token exchange**: PG18 OAuth + RFC 8693 + MCP's OAuth 2.1 rules permit per-agent, audience-bound DB credentials; today agents get long-lived DSNs.
6. **Parse-cache-aware chargeback**: attribute cost per tenant from a fingerprint→queryid map without `pg_read_all_stats`.
7. **Vector-aware admission control**: classify ANN queries from the plan and queue them separately to stop one tenant starving all ([pgvector](https://github.com/pgvector/pgvector)).
8. **Little's-Law pool sizing**: adaptive per-tenant server-connection limits instead of static `default_pool_size`.
9. **Data-residency routing as a compliance product**: HeliosProxy shows the mechanism; nobody ships it with a real policy language.
10. **A formally specified router**: publish a TLA⁺-checked transaction-pinning and GUC-replay state machine as the correctness argument.
