# Writable-primary acquisition failover

`bash tests/conformance/failover/run.sh` starts a disposable PostgreSQL primary and a physical streaming replica, plus the workspace proxy. It uses ports 55442/55443/6443 and removes its containers, network and volume on exit. Set `PGPROXY_BINARY` for another built binary. PostgreSQL 18 is the default; `PGPROXY_FAILOVER_IMAGE` selects another image with PostgreSQL tools.

The five gates verify that an unpromoted replica cannot receive user writes; a reachable demoted primary with two idle pooled sockets is retired before user SQL; an externally promoted replica accepts new connections; committed data is preserved with one new write; and a transaction interrupted after its write fails and is not replayed after backend recovery. The fixture first stops the primary to test unpromoted-replica rejection, then restarts it and makes it read-only to test reachable-primary demotion. It stops that old primary again after promotion. A read-only server setting is a controlled test mechanism, not production fencing. PGProxyScale performs no promotion and provides no distributed fencing. A server role can change after any primary check, so the PostgreSQL deployment still needs an external failover authority that prevents concurrent writable primaries.

Configuration uses `[[databases.failover]]` with `host`, `port`, and optional `backend_tls`. Omitted TLS inherits the primary route's verified TLS configuration. Alternate endpoint certificates must match that inherited server name, or specify their own CA/name. At most seven alternates are accepted. Failover requires terminated client authentication and writable-primary checks. Credential providers resolve separately for each physical endpoint. Returned pooled connections carry a shared route generation and lease expiry.

Failover happens during backend acquisition before user SQL is sent. In-flight transactions and uncertain results fail; clients must reconcile their own write outcomes. Blocking operating-system DNS resolution remains outside the socket acquisition deadline. Real IAM/Vault credentials, encrypted replicated failover, external fencing, WAN faults, long soak and independent security review require separate deployment-specific acceptance.
